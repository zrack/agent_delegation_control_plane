# Threat Model

**Scope:** local viewer, bounded untrusted record import and optional model-agent runner. No full security audit or production assurance is claimed.

| Threat ID | Asset/trust boundary | Threat/abuse case | Mitigation | Verification | Residual risk | Owner | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T-001 | Supplied logs to operator conclusion | Missing/inconsistent authority appears permitted | Explicit unknown state; identity/parent checks; no default permissions | Domain contract tests | Records remain unauthenticated/self-reported | Maintainer | Bounded |
| T-002 | Evidence fields to HTML | Record text becomes executable markup | Escape record text; bounded structural import; numeric timestamp display; restrictive content policy | Source review and server header check | Imported text remains untrusted; browser checks observed zero injected elements | Maintainer | Bounded |
| T-003 | Static server to repository | Reading private files, directory traversal or remote Host | IPv4 loopback, asset allowlist, local Host check, no writes | HTTP contract tests | Loopback is not user authentication; local processes can access synthetic assets | Maintainer | Bounded |
| T-004 | Partial evidence to findings | A malformed timestamp hides a known scope violation | Evaluate independent fields; preserve violation and incomplete state together | Mixed-evidence regression checks | Missing capability data can prevent a scope conclusion | Maintainer | Bounded |
| T-005 | UI wording to operational assumption | Flagging is mistaken for blocking or identity proof | Synthetic/retrospective labels; no enforcement controls | Three-case UI review | Real prevention/identity would require separate architecture | Maintainer | Bounded |
| T-006 | Local key to static server/browser | Credential disclosure through source or request logs | Ignored approved env file, narrow static allowlist, no browser API client, safe diagnostic metadata | Ignored/tracked/permission checks and no-key-in-artifacts check; HTTP rejection checks | Local privileged software can still read local secrets | Maintainer | Bounded local setup |
| T-007 | Model tools to filesystem | Model chooses arbitrary files/actions or skips required evidence | Tools accept no paths; fixed generated account/summary; dynamic role/action availability and explicit callback bindings | Offline SDK replay/negative tests plus actual run | No generic agent policy enforcement or external IAM proof | Maintainer | Named workflow only |
| T-008 | File input to browser resource use | Small accepted inputs amplify ancestry/findings and freeze the viewer | 1 MiB/record/field intake limits; shared 50,000-unit work budget; keyed deduplication; 1,000 findings plus global incomplete sentinel; compared evidence serialized on demand | Within-limit 200-by-200 and capability-heavy regressions, direct-caller limits, retained-violation/unknown semantics and normal-run recovery | Finite synchronous local parsing/rendering cost remains; work units are not a wall-clock guarantee; no general ingestion service | Maintainer | Bounded |
| T-009 | Imported label to provenance belief | Arbitrary file claims to be an authenticated model run | Explicit imported source-claim wording and visible identity/completeness limits | Browser label inspection | Local manifests are hashes, not signatures | Maintainer | Disclosed |
| T-010 | Model-written code to host and operator conclusion | Generated code reads host data, exhausts resources or invents a correct outcome | Fixed pilot gateway; actor/capability/time checks before execution; isolated non-root Docker with no network/host mounts; read-only root, bounded tmpfs/resources; separate collector and deterministic oracle | Real isolation/failure tests, SDK replay, physical artifact and capture checks | Docker engine is trusted; named workload only; no escape audit, general runtime authorization or authenticated evidence | Maintainer | Pilot boundary tested |

| T-011 | Saved browser evidence to restored conclusions and privacy | Tampered saved records appear trusted, or sensitive evidence remains on a shared profile | Versioned 20-run / 2 MiB collection; repeat bounded intake and fresh evaluation; escaped output; visible restoration/save failures; clear-only-application-key control; no automatic eviction | Persistence tests cover malformed/duplicate records, quota/access failures, limits, replacement and clearing; browser reload and evidence review | Browser-local storage is unencrypted and origin/profile scoped; no authenticity or backup guarantee; other tabs may retain loaded copies | Maintainer | Bounded local persistence |

See [architecture](../../ARCHITECTURE.md), [diagrams](README.md) and [privacy guidance](../PRIVACY.md). Revisit before customer data, authentication, shared/server persistence, broader binding or enforcement. This is a bounded model, not a full security audit.
